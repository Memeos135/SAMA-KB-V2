# System Change Management Domain

Domain 3.4 requires a governed change management process so that changes to information assets (applications, software, devices, data) are classified, risk-assessed, tested and approved before deployment to production. Control requirements cover change governance policy, requirement definition and asset-owner approval, Change Advisory Board endorsement, system acquisition and development, testing (including UAT and prohibition on using production data in test), security requirements, release management, and emergency-change handling with post-implementation review and root cause analysis. Explicitly cross-references the SAMA Cyber Security Framework for security sign-off on changes.

**Regimes:** governance/risk
